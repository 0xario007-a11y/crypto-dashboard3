# Crypto Dashboard

A single-page crypto project dashboard, embeddable in Notion, hosted entirely
on GitHub Pages. No backend, no database, no framework.

**Notion** (project metadata) → **GitHub Action** (sync job) → **`projects.json`**
(static file) → **`index.html`** (client) → **CoinGecko** (live market data,
fetched directly from the browser).

---

## 1. Repository layout

```
index.html                     — the entire app: HTML + CSS + JS, one file
projects.json                  — generated by the Action; ships as an empty
                                  placeholder so the first deploy shows an
                                  onboarding screen instead of an error
fetch-notion.mjs                — Node script the Action runs to sync Notion
favicon.svg
README.md
.github/workflows/sync-notion.yml
```

`.github/workflows/` is the only folder in the project, because GitHub Actions
requires that exact path. Everything else lives at the repository root.

## 2. Set up the Notion database

Create a database with these properties (names must match exactly):

| Property        | Type       | Required | Notes                                      |
|------------------|-----------|:--------:|---------------------------------------------|
| Project Name     | Title      | ✅       | Shown as the dashboard heading              |
| Slug             | Text       | ✅       | Used in the URL as `?slug=`, must be unique, no spaces |
| CoinGecko ID     | Text       | ✅       | See below for how to find it                |
| Active           | Checkbox   | ✅       | Only checked rows get a live dashboard      |
| Sort Order       | Number     |          | Controls ordering on the project list page  |
| Description      | Text       |          |                                              |
| Category         | Select or Text |      |                                              |
| Website          | URL        |          |                                              |
| Whitepaper       | URL        |          |                                              |
| GitHub           | URL        |          |                                              |
| Documentation    | URL        |          |                                              |
| Twitter/X        | URL        |          |                                              |

**Finding a CoinGecko ID:** go to the coin's page on coingecko.com — the ID is
the slug in the URL. For `https://www.coingecko.com/en/coins/bitcoin` the ID
is `bitcoin`. It's also visible in the API response of
`https://api.coingecko.com/api/v3/coins/list`. Never hand-type a guess; the
sync script and the dashboard both read this value as-is and pass it straight
to CoinGecko.

**Adding a new dashboard later is just: add one row, check Active.** Nothing
else needs to change — no code, no JSON, no manual deploy.

### Create the Notion integration

1. Go to [notion.so/my-integrations](https://www.notion.so/my-integrations) → **New integration**. Give it a name, save the token — this is `NOTION_TOKEN`.
2. Open your database in Notion → `•••` menu → **Connections** → connect your new integration.
3. The database ID is the 32-character string in the database URL:
   `notion.so/workspace/<DATABASE_ID>?v=...` — this is `NOTION_DATABASE_ID`.

## 3. Deploy

1. Push this repository to GitHub.
2. **Settings → Secrets and variables → Actions → New repository secret**, add:
   - `NOTION_TOKEN`
   - `NOTION_DATABASE_ID`
3. **Settings → Pages** → Source: `Deploy from a branch` → Branch: `main` / `root`.
4. **Actions tab** → "Sync Notion → projects.json" → **Run workflow** to sync immediately, rather than waiting up to 15 minutes for the schedule.
5. Visit your Pages URL. With no `?slug=`, you'll see the list of active projects. Append `?slug=bitcoin` (or whichever slug you used) for a single dashboard.

### Embedding in Notion

Use a Notion **Embed block** pointing at your Pages URL (optionally with
`?slug=...`). GitHub Pages is served over HTTPS, which Notion's embed
requires.

## 4. How the moving parts work

- **Sync (`fetch-notion.mjs`)** — queries the whole Notion database, validates
  that every row has a name/slug/CoinGecko ID and that no two rows share a
  slug (the Action **fails loudly** if slugs collide, rather than silently
  picking one), sorts by Sort Order, and writes `projects.json`. It skips
  committing if nothing actually changed, so you don't get a noisy commit
  history from timestamp-only diffs.
- **Metadata refresh** — the dashboard re-checks `projects.json` every 60s in
  the background and only re-renders if `updatedAt` actually changed, so a
  Notion edit (renamed project, flipped Active, new row) shows up without a
  manual page reload.
- **Market data refresh** — price/market-cap/etc. re-fetch from CoinGecko
  every 30s while a single-project dashboard is open.
- **Caching** — `projects.json` is fetched with `cache: "no-cache"`, which
  makes the browser revalidate with the server (ETag/Last-Modified) rather
  than blindly trust a local copy, while still allowing a fast `304` when
  nothing changed. Market data and chart data are additionally cached in
  `localStorage` per project/timeframe, so a transient CoinGecko error or a
  flaky connection shows the last-known data (clearly marked "cached") instead
  of a blank error screen.
- **Chart** — Chart.js + `chartjs-chart-financial` render real OHLC candles
  from CoinGecko's `/coins/{id}/ohlc` endpoint for 24H/7D/30D/90D/1Y. Note
  CoinGecko itself determines candle granularity by range (e.g. 30-min candles
  for 24H, daily candles for 1Y) — this is a CoinGecko API characteristic, not
  something the dashboard can override.

## 5. States handled

| Situation                              | What the user sees                                      |
|-----------------------------------------|-----------------------------------------------------------|
| First deploy, Action hasn't run yet     | Onboarding screen with setup checklist (not an error)     |
| No `?slug=`                             | Grid of all active projects with live mini-prices         |
| Unknown slug                            | "Project not found" + link back to the list                |
| Project exists but `Active` unchecked   | "Currently inactive" message                                |
| Project has no CoinGecko ID set         | Clear config-error message, not a silent blank chart       |
| Invalid/unknown CoinGecko ID            | "Invalid CoinGecko ID" message naming the bad value         |
| CoinGecko temporarily down/rate-limited | Falls back to last cached data, marked stale, retries       |
| No internet                             | Dedicated offline screen, auto-recovers on reconnect        |
| Empty Notion database                   | Onboarding-style "no active projects" message               |

## 6. Testing checklist

Manual steps to verify after deploy or after any change:

1. **Fresh deploy, before first sync** — visit the Pages URL immediately after
   enabling Pages, before running the Action → should show the onboarding
   screen, not a JSON parse error.
2. **Run the sync manually** (Actions tab → Run workflow) with one Active
   Notion row → reload → project list should show it.
3. **Visit `?slug=<your-slug>`** → full dashboard loads: logo, price, 24h
   change, all 12 stat cells, candlestick chart, all 5 timeframe buttons work.
4. **Visit `?slug=doesnotexist`** → "Project not found" screen.
5. **Uncheck Active in Notion, re-sync** → dashboard for that slug now shows
   "currently inactive" within ~60s without a manual reload (metadata
   re-check).
6. **Add a second row in Notion with a duplicate slug, re-sync** → the Action
   run should **fail** (red X in Actions tab) with a clear "Duplicate Slug"
   message, and `projects.json` should remain unchanged.
7. **Enter a bogus CoinGecko ID on a row** → its dashboard shows "Invalid
   CoinGecko ID", not a blank/broken layout.
8. **Turn off Wi-Fi while a dashboard is open** → offline screen appears;
   turning Wi-Fi back on auto-recovers.
9. **Resize to a phone width** → stat grid reflows to 2 columns, project grid
   reflows, chart remains usable.
10. **Keyboard-only navigation** — Tab through the project list and the
    timeframe buttons; focus outlines should be visible throughout.

## 7. Production audit

Checks performed on this codebase before delivery, and their outcome:

- **JS syntax** — `fetch-notion.mjs` and the inline dashboard script both
  pass `node --check`.
- **HTML structure** — tag balance verified (all `div`/`span`/`a`/`button`
  pairs matched); every `id` referenced by `getElementById` in the script
  exists in the markup (static or template-generated).
- **DOM IDs** — no duplicate static IDs; dynamically generated markup (list
  cards, stat cells) uses classes/data-attributes instead of IDs to avoid
  collisions when repeated.
- **Broken links** — external links (CoinGecko, per-project Website/Whitepaper/
  GitHub/Docs/Twitter) all render as `<a target="_blank" rel="noopener">`;
  project URLs come from Notion so they're validated at sync time only in the
  sense that empty ones are simply omitted from the link row rather than
  rendered broken.
- **404s** — a missing `projects.json` (shouldn't happen since it's committed,
  but covered anyway) and a 404 from CoinGecko for a bad coin ID are both
  handled with specific, worded states rather than a generic failure.
- **GitHub Pages compatibility** — no build step, no server-relative absolute
  paths, no reliance on directory indexes; all asset references (`favicon.svg`,
  `projects.json`) are relative so the site works whether served from a root
  domain or a `/repo-name/` project path.
- **GitHub Actions compatibility** — workflow uses `permissions: contents:
  write` (required to push the commit) and `concurrency` (prevents two
  overlapping syncs from racing on the same commit).
- **Caching correctness** — `no-cache` fetch mode confirmed to still allow
  conditional `304` responses (it forces revalidation, not a bypass), so
  repeat visits don't re-download `projects.json` unnecessarily.
- **Security** — the Notion token only ever exists inside the GitHub Actions
  runner (as a secret) and is never present in any file served to the
  browser; the client only ever talks to CoinGecko's public, keyless
  endpoints.
- **Memory leaks** — `setInterval` timers (market refresh, metadata recheck)
  and the Chart.js instance are explicitly cleared/destroyed on every
  re-render (`clearTimers()`, `chart.destroy()`), so navigating between
  states repeatedly (e.g. switching slugs) doesn't accumulate timers or
  orphaned canvases.
- **Accessibility** — visible `:focus-visible` outlines on all interactive
  elements (links, buttons, timeframe toggles); `prefers-reduced-motion` is
  respected by disabling the skeleton shimmer and pulse animations.
- **Mobile** — stat grid and project grid both use responsive `grid-template-
  columns` breakpoints; layout tested down to narrow viewports.

One limitation worth stating plainly rather than glossing over: CoinGecko's
free public API is unauthenticated and rate-limited. Under heavy traffic to a
single deployed dashboard, individual visitors could occasionally see the
"cached data" fallback state during a burst of 429 responses. This is an
inherent tradeoff of the "no backend, no API key" requirement — the
alternative would require a proxy (a backend), which was explicitly out of
scope.
